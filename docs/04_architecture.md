# 04 Architecture

## Pipeline
```
Evidence (one sample from inputs/evidence_samples.json)
      |
Schema + evidence validation ---- invalid ----> INPUT_ERROR (no detector runs)
      |
12 detectors  ->  PASS / FAIL / INSUFFICIENT
      |
Timestamped findings  (reports/findings.json)        <- end of Phase 1
      |
Control mapping (NIST CSF 2.0, ISO 27001)
      |
Risk register (likelihood x impact)  -->  Monte Carlo (top risks)
      |
Remediation (matrix and plan)
      |
Re-test: same detector on updated evidence (FAIL -> PASS)
      |
Business decision
```

## Components
| Layer | Files |

## Design rules
- **Evidence is not a verdict.** Missing, null or `unknown` values become INSUFFICIENT, never FAIL. Only malformed values are INPUT_ERROR.
- **One detector per control**, all inheriting `BaseDetector`, which also enforces the coverage rule: every applicable asset gets a finding.
- **Time is measured from the evidence's `collected_at`,** so results do not depend on the day the engine runs. `detected_at` is always generated by the engine.
- **Data tiers live only in `company/asset_inventory.yaml`.**

## Framework mapping
`controls/control_map.csv` has one row per control (12 rows). Each control is mapped to the single best-fit requirement in NIST CSF 2.0 and in ISO/IEC 27001:2022 Annex A, with the evidence it relies on and a rationale. The mapping gives context only. It is not a certification, and it is kept separate from detection, risk and decision.

## IDs
```
DET-MFA > FND-MFA-01 > CTRL-IAM-001 > RISK-MFA-01 > REM-MFA-01 > TEST-MFA-01
```
Assets use `AST-`, assessments `ASM-`, evidence records `ACC-0001`, `DEV-0001` and similar.

## Test gates
- Gate 1: schemas and validators.
- Gate 2: 12 detectors (PASS, FAIL and re-test, INSUFFICIENT, INPUT_ERROR), finding generator, integration.
- Risk calculator and Monte Carlo accuracy tests.
